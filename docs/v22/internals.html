How It Works Inside

You call render(config). Four things happen in sequence. This document shows exactly what each step does, which library is responsible, and what the v22 source code actually says.

The 4-Step Pipeline

1
Validate the config
json-renderers-guard
Before anything is built, the config object is validated. The guard checks both groups — Spec fields (type, data, columns) and Mount fields (targetHtmlId, classToApply, appendPosition). If anything is wrong, it throws a clear error immediately. 
// src/v22/index.js — Step 1
guardFunc(config); // throws if invalid — no DOM work happens yet
2
Build a JSON Spec (the AST)
json-renderers-specs
buildSpec() is called with type, data, columns, and options. It calls json-renderers-specs which produces a pure JSON object describing the entire component structure — tags, attributes, classes, rows, headers. No DOM is created yet. This is called specAsJsonToDom. 
// src/v22/buildSpec/index.js — Step 2
import jsonRenderBuild from "json-renderers-specs";

const specAsJsonToDom = jsonRenderBuild({
  type:    localType,
  data:    localData,
  columns: localColumns,
  options: localOptions,
});
3
Convert the spec to real DOM nodes
@keshavsoft/json-to-dom
The JSON spec is handed to @keshavsoft/json-to-dom. This library reads the spec and calls document.createElement() for every tag in the tree — creating real, live HTMLTableElement, HTMLSelectElement, HTMLInputElement nodes. It also resolves the targetHtmlId and mounts the finished nodes into the container. 
// src/v22/index.js — Step 3 & 4 combined
const dom = jsonToDom({
  jsonSpec:      spec,           // the AST from Step 2
  targetHtmlId:  config.targetHtmlId,
  appendPosition: config.appendPosition,
  showLog
});
4
Mount into the page & return
json-renderers (this repo)
The component is now inside document.getElementById(targetHtmlId). The render() function returns the mounted DOM element. Your component is live on the page. 
// src/v22/index.js — return
return dom; // the mounted HTMLElement

Key point: json-renderers itself does not write DOM directly. It is the coordinator. The actual DOM node creation is entirely inside @keshavsoft/json-to-dom. The spec construction is entirely inside json-renderers-specs. This repo wires them together.

The Complete v22 Source — index.js

Here is the full orchestrator file, all 41 lines:

import registerGlobal from "./registerGlobal.js";
import guardFunc      from "json-renderers-guard";
import jsonToDom      from "@keshavsoft/json-to-dom";
import buildSpec      from "./buildSpec/index.js";

// Main orchestrator: validate → build spec → create DOM → mount
const render = (config = {}) => {
    guardFunc(config);                      // Step 1: validate

    const spec = buildSpec({                 // Step 2: build JSON AST
        inColumns: config.columns,
        inData:    config.data,
        inType:    config.type,
        inShowLog: config.showLog,
        inOptions: config.options
    });

    const dom = jsonToDom({                  // Steps 3 & 4: create DOM + mount
        jsonSpec:       spec,
        targetHtmlId:   config.targetHtmlId,
        appendPosition: config.appendPosition,
        showLog:        config.showLog
    });

    return dom;
};

registerGlobal(render); // attaches window.ks.jsonRenderers.render

export { render };
export default render;
