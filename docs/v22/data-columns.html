🗄️ Doc 3 · Data & Columns

Data & Columns in Detail

data and columns are the two most important things you supply. Together they form the common dataset — a single source of truth that any component type can consume. This document explains exactly what each should look like.

📦
data
Array of row objects

data is always an Array. Each element in the array is a plain JavaScript object representing one record (one row in a table, one entry in a form).

The keys of each object must match the columnName values in your columns array.

Shape

const data = [
  {
    itemName:    "0.09/30mm High Tensile Bolt",
    category:    "Fasteners",
    baseUnit:    "kgs",
    openingRate: "1200.00/kgs",
    inStock:     true,
    notes:       "Grade 8.8 tensile steel bolt for industrial heavy machinery."
  },
  {
    itemName:    "0.11-25 Galvanized Wire Coil",
    category:    "Raw Materials",
    baseUnit:    "kgs",
    openingRate: "1450.00/kgs",
    inStock:     true,
    notes:       "Zinc coated anti-corrosive high-durability wire coil."
  }
  // ... more records
];

Each object in data is one row. The keys are the column names — they must match the columnName field in your columns definitions.

🗂️
columns
Array of column definition objects

columns is always an Array of objects. Each object defines one column — its machine name, its human label, its input type, its display width, and any constraints.

This is your schema. The same columns array drives every component type — a table, a form, a select dropdown all read from the same definition.

Fields of Each Column Object

Field Type Description
columnName required string The machine key. Must match the key in each data object.
label required string The human-readable header shown in tables and form labels.
type required string The input type for this column. Controls how forms and tables render it.

text select checkbox textarea
width optional string CSS width for this column in the table. e.g. "240px", "120px"
placeholder optional string Placeholder text for form inputs. e.g. "Enter item description..."
required optional boolean Marks this field as required in form rendering.
options only for select string[] Available choices for type: "select" columns. e.g. ["Fasteners", "Raw Materials"]

Full Example (the real columns.json)

const columns = [
  {
    columnName:  "itemName",
    label:       "Item Name",
    type:        "text",
    width:       "260px",
    placeholder: "Enter item description...",
    required:    true
  },
  {
    columnName: "category",
    label:      "Category",
    type:       "select",
    width:      "180px",
    options:    ["Fasteners", "Raw Materials", "Extrusions", "Electrical"],
    required:   true
  },
  {
    columnName:  "baseUnit",
    label:       "Base Unit",
    type:        "text",
    width:       "120px",
    placeholder: "e.g. kgs, pcs, boxes"
  },
  {
    columnName: "inStock",
    label:      "In Stock",
    type:       "checkbox"
  },
  {
    columnName:  "notes",
    label:       "Specifications / Notes",
    type:        "textarea",
    placeholder: "Enter technical specifications..."
  }
];
🔗
How data and columns connect
The key-to-columnName link

The columnName in each column definition is the bridge to your data:

// columns says: columnName is "itemName"
{ columnName: "itemName", label: "Item Name", ... }

// data record uses the same key: "itemName"
{ itemName: "0.09/30mm High Tensile Bolt", ... }

// Result in the table cell:
// <td>0.09/30mm High Tensile Bolt</td>

The system reads the label from columns to build the table header, and reads the value from data using the same columnName key to fill each cell.
